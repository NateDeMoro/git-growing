## Contract fields used (read from contract.ts on main; conform, never rename)
contract.ts does not exist yet. Before writing any component, read it and map each item below to its real field name. If something is missing, ask the coordinator. Do not add it yourself.
- **SceneFrame:** timestamp; layers (height ft, temperature, wind speed, wind direction), which give the 5 ft and 30 ft readings; summary (inversion °F, speed shear, direction shear, Delta T, RH); sun elevation; cloud %; rain rate; gusts; pressure; look-ahead (next beat, status 3 sim-hours later).
- **Assessment:** status, reasons, droplet recommendation (class, or "none" with a cause), single-station result.
- **Reason:** rule id, status, text, source tag.
- **Status:** GO / CAUTION / STOP.
- **Product:** name, volatility band, label wind max, label minimum droplet class, "check label" flag.
- **DropletClass:** the ordered S572 classes and the how-to-get-it hint from droplets.ts.
- **LogEntry:** time, mode, status, triggers, readings, droplet class.
- **ForecastWindow:** start, end, status, plus the next safe window and early warning.
- **Beats:** the label and frame index from the sim file shape.
- **thresholds.ts:** rule id, cutoff, kind (standard / guidance / heuristic), source title and URL.
- FrameProvider hook: current frame, assessment, mode, selected product, and the setters the provider exposes.

## Ordered steps
1. **Contract read.** Read contract.ts, thresholds.ts, droplets.ts, products.ts and the FrameProvider. Write down the field mapping above as comments only where a component needs it.
2. **Theme and shell.** Dark control-room tokens: near-black background, glowing green, amber and red with matching glow shadows, large type and high contrast for a projector. Self-hosted fonts through next/font (a local or bundled font, never a Google CDN fetch at runtime). Header "Spray or Wait · by GitGrowing", site name "UA Yuma Mesa Farm" from site.ts, and the page title. Tabs: Now, Forecast, Log.
3. **Mock data.** Use `tests/fixtures/frames48.json` if it's on main. If not, write a tiny 48-frame mock that includes one inverted evening, one windy hour and one rain hour. Add the stub assessment: a few threshold checks that read thresholds.ts, enough to show all three colors. Wire it through the provider's assessment slot, or locally if the provider has none.
4. **log.ts.** The store appends entries, caps at 5,000 (oldest dropped), reads, clears and subscribes. localStorage runs inside try/catch and falls back to memory when storage is missing or throws. CSV export has a fixed header and quotes any field that holds a comma, quote or newline (inner quotes doubled). The reasons go in one cell. Write tests/log.test.ts first, then the code; it must pass before step 5.
5. **Now tab, right column.** StatusCard (big status, top reason), ReasonList (worst first, source tag chip), ReadingsCard (5 ft and 30 ft side by side), DropletAdvice (class, hint, coverage tradeoff, "no droplet size makes this safe" state), StationCompare (tower verdict next to single-station verdict, and an AZMet slot that shows a placeholder until W6), ProductPicker (with the "check label" flag), MastSVG (warm-over-cool band when inverted), WindCompass (one arrow per height).
6. **WhyLimits panel.** Lists every rule from thresholds.ts with its cutoff, kind badge and source link. Heuristic rules are labeled "heuristic, tunable". It's a collapsible section on the Now tab.
7. **Layout.** Now tab: the Phase 0 Scene3D placeholder takes about 60% on the left, the right column scrolls, and on narrow screens the columns stack. The playback bar runs full width at the bottom, with a collapsible chart strip above it holding TowerChart and WindChart.
8. **PlaybackBar.** Live/Simulate toggle, play/pause, speeds of 0.25, 1 and 6 sim-hours per second, a scrubber with beat markers, and a "next beat" button. Locally it drives the playhead over the 48 frames. In the store, playback state and actions sit behind the same interface W6 will back with week.json.
9. **Charts (recharts).** TowerChart: both temperatures over the last 24 sim-hours, with inverted spans shaded. WindChart: both speeds, with shaded bands under 3 mph and over 10 mph (or the label max).
10. **Forecast tab.** ForecastStrip (7 days, one cell per hour colored by status), NextWindowCard, EarlyWarningBanner (an explicit "none" state, plus the look-ahead text "storm arriving in 3 hours" in sim mode), WindowDial (24-hour ring colored by each upcoming hour). Build windows from the mock frames with a local merge until W5's forecast.ts lands.
11. **Log tab.** LogTable: newest first, status-change rows highlighted, status filter, Download CSV (a Blob download), Clear (with confirm). Append an entry when the mock status changes, so the table fills during playback.
12. **DemoPanel and hotkeys.** One global key listener that ignores input and select focus. Backtick toggles the panel, which is hidden by default. Hotkeys work while it's hidden: 1 to 6 jump to beats A to F, space pauses, [ and ] step through the three speeds, R clears the log, F flies to overview, V toggles 2D/3D, L switches Live and Simulate. F and V only call store callbacks. The panel lists the keys and the beat jump buttons.
13. **Verify.** Run `npm run build`, `npm test` and `npm run lint` in the background. Run `npm run dev`, click through all three tabs and every hotkey with the mock, check there's no horizontal scroll at 1280 and 1920 wide, then stop the dev server.

## Tests
- `tests/log.test.ts` only:
  - CSV quotes a field with a comma, a quote and a newline.
  - A plain field stays unquoted.
  - The store falls back to memory when localStorage throws on get and on set.
  - The cap holds at 5,000 entries.
  - Clear empties the store.
- No component tests (accepted gap per plan).

## Risks
- **Contract drift.** Inventing or renaming fields breaks W6 and W7. Read contract.ts first and ask before adding anything.
- **Merge overlap with W7.** page.tsx and the Now layout also host the 3D slot. Keep the slot a single child with the placeholder's props, and stay out of `src/components/scene/`.
- **Stub leakage.** The stub assessment must not ship as if it were the engine. Keep it in one file that W6 deletes.
- **SSR and storage.** localStorage and the key listener run only on the client. Guard log.ts, or the build and prerender fail.
- **Fonts.** next/font/google downloads at build time, which is fine for offline demo runs but fails a build with no network. Prefer next/font/local with a committed font file.
- **Recharts performance at 6 sim-hours per second.** Cap the series to a 24-hour window and turn chart animation off.
- **Hotkey conflicts.** Space scrolls the page, and keys fire while the user is typing. Call preventDefault and skip form fields.
- **Projector contrast.** Amber on dark can wash out. Check readability at a distance, and pair each color with its text label, never color alone.
- **Lockfile conflicts.** W4 likely adds no dependencies (recharts comes from Phase 0). If it does, follow plan section 9.
